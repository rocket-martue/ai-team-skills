# 共通規約

ガネーシャ・メジェド・adversary が従う規約。ここを直したら、全員に反映される。

## 言語

- 会話・計画書・レビュー・コミットメッセージは日本語

## コーディング

- PHP は WordPress Coding Standards 3.0.0 以降に準拠し、phpcs.xml で定義された WordPress Custom Standard に従う
- インデント、スペース、命名規則などの WordPress コーディングスタイルを維持する
- 出力は必ずエスケープ、入力は必ずサニタイズする
- フォーム処理には nonce 検証と権限チェックを入れる
- SQL は `$wpdb->prepare()` を使う
- 翻訳関数を使い、テキストドメインを統一する
- CSS／SCSS はモバイルファースト

## 作業の進め方

- 読んでいないコードは変更しない
- 十分に調査せずに編集に飛びつかない
- 秘密情報（API キー、DB 情報、wp-config.php）は扱わない、コミットしない
- タスクの記録は `docs/tasks/<タスク名>/` に置く（plan.md、review.md）
- タスクは1本ずつ進める。別タスクの未コミットの変更が残っている作業ツリーで始めない
- 編集の制限（`.claude/hooks/guard-code-edit.mjs`）が見るのは Edit / Write などの編集ツールだけ。Bash・PowerShell 経由の書き込み・読み取り（リダイレクト・`sed -i`・`Set-Content`・`cat` など）は止まらない。コードの編集と秘密情報の読み取りを Bash・PowerShell で回り込まない（フックと settings.json の Read の禁止は、うっかりを防ぐ柵で、壁ではない）
- 次は確認が出る（まーちゅうの確認を取る）。`docs/team/`（この規約・作業の流れ・Ganesha.md）、リポジトリの根の `CLAUDE.md`、`.claude/`（worktree の中の `.claude/` を含む）の編集。`git stash`・`restore`・`clean`・`rm`・`branch`・`worktree remove` などコミット前の作業やブランチを消せる git のコマンド
- コマンドが確認で止められた・拒否されたときは、別の書き方で回り込まずに止まる。報告には、止まったコマンドそのものと、settings.json のどのルールに当たったか、それが ask（まーちゅうが確認のダイアログで通せる）か deny（通せない。別の書き方を決める必要がある）かを添える。どのリストにも無いコマンドで確認が出たときは、その旨を書く
- クライアント名・実ドメイン・slug をコード・テスト・コミットメッセージに書かない

## チーム

| メンバー | ツール | 役割 |
| --- | --- | --- |
| まーちゅう | GitHub | 要件決定、計画の承認、最終確認、マージ |
| ガネーシャ | Claude Code（メイン） | 計画書の作成、メジェドへの実装依頼、差分レビュー、頼まれたときのコミット・PR 作成、PR に付いた指摘の検証と返信 |
| メジェド | Claude Code（サブエージェント `mejed`・既定は Haiku。plan.md で Sonnet を選べる） | 計画書に沿った実装、指摘の修正 |
| adversary | Claude Code（サブエージェント `adversary`・Fable） | 壊しに来る役。計画の承認前に、1つの計画につき1回だけ、ガネーシャに呼ばれて計画書を壊す側から読み、指摘だけを返す。直さない |
| 健さん | Codex CLI（外部委託業者。スキル `codex` から呼ぶ） | 読むだけの相談（ガネーシャ・メジェド）、読むだけのレビュー（ガネーシャ）、画像の生成（メジェド）。実装は頼まない。承認前の確認（`consult`）、チェックが2回以上落ちたときの確認（`consult`）、PR の前の確認（`review`）の中心 |

健さんに頼むときの決まり（詳しくは `.claude/skills/codex/SKILL.md`）：

- ラッパー（`invoke-codex.ps1`）を通して呼ぶ。`codex` を直接呼ばない
- 頼みの文に、秘密情報のファイルを開かないこと・ファイルを書き換えないことを必ず入れる。秘密情報のファイルを頼みの文に貼らない。`review` は頼みの文を渡せないので、同じ決まりを健さんの AGENTS.md で持たせる
- 健さんの答えはそのまま採らない（Fable の指摘と同じく、一次データで確かめる）
- 呼ぶたびに、契約しているプランの Codex の枠を使う。1回の依頼は1つにまとめる

Fable と健さんの指摘も、ガネーシャが一次データで確かめてから review.md に書く（承認前の指摘は plan.md に反映する）。簡単な修正の道（workflow.md）では、健さんの指摘は PR 本文に書き、review.md は作らない。

PR に付いた指摘（Copilot・人）は、ガネーシャが検証して review.md に書く。コードの指摘はメジェドが、コード以外（`.md`）の指摘はガネーシャが直す。簡単な修正の道（workflow.md）では、PR に付いた指摘はスレッドの返信と PR のコミットに残し、review.md は作らない。
スレッドへの返信はガネーシャが行う。再レビューを頼むかは、まーちゅうが決める。
