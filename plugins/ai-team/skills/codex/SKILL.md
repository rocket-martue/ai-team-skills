# codex（健さんに頼む）

健さんは、チームに外から入っている外部委託業者（Codex CLI）。頼めるのは次の3つだけで（表の `save-code-review` と `make-patch` は、健さんを呼ばないモード）、**実装は頼まない**（実装はメジェドの担当。健さんがファイルを書き換えると、フックも計画の承認も通らないため）。

| モード | 中身 | 使う人 |
| --- | --- | --- |
| `consult` | 読むだけの相談。既定のモード | ガネーシャ・メジェド |
| `review` | 読むだけのレビュー（未コミットの変更、または基準ブランチとの差分） | ガネーシャ |
| `image` | 参照画像を渡して、画像を1枚作る。できた画像はリポジトリに置かない（置くのはメジェド） | メジェド |
| `save-code-review` | `/code-review` の結果を、健さんの返事と同じ決め方で保存するだけ（codex は呼ばない） | ガネーシャ |
| `make-patch` | コミットの前の差分を、秘密情報を照らしてからパッチのファイルにするだけ（codex は呼ばない。`/code-review` に渡すため） | ガネーシャ |

adversary（Fable）はこのスキルを使わない（計画書や PR の差分を読む役）。計画の承認前の「壊しに来る役」は、レビューの道（workflow.md の言葉の決まり）で健さんを選んだとき、ガネーシャが `consult` で健さんに頼む（下の「壊しに来る役を頼むとき」）。

健さんの設定（キャラ・請け負う範囲）は、各 PC の `<CODEX_HOME>/AGENTS.md`（既定は `~/.codex/AGENTS.md`）にある。見本はテンプレートの `repo-files/codex/AGENTS.md`。

## 手順

1. 依頼を、健さんが1回で答えられる1つの頼みにする。会話の経緯をそのまま渡さない
2. 頼みの文を一時ファイルに書く。置き場所はセッションの scratchpad（`<一時ディレクトリ>/claude/` の下。フックが編集を通すのはここだけ）。`review` は頼みの文を使わない
3. リポジトリの根から、Bash ツールで次の文字列で呼ぶ（allow に入っているのはこの形だけ）

   ```
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File "${CLAUDE_PLUGIN_ROOT}/skills/codex/scripts/invoke-codex.ps1" -Mode <consult|review|image> -Task <タスク名> [-PromptFile <一時ファイル>] [-Image "<画像1>|<画像2>"] [-Base <基準ブランチ>]
   ```

   - worktree（`.claude/worktrees/<名前>`）で作業しているときは、`-WorkingDirectory <パス>`（リポジトリの根からの相対パス）を付ける。健さんはそのパスを作業の根にして読む
   - `-Task` は必須（返事を `docs/tasks/<タスク名>/codex/` に残すため。無ければラッパーが止まる。そこが Git に無視されていないリポジトリでは、返事は一時ディレクトリに残る）
   - `review`：コミット前は何も付けない（`--uncommitted`）。コミット済みを見るときは `git fetch origin` のあと `-Base origin/<既定ブランチ>`（diff-reviewer と同じ基準で比べるため）。`-Base` で呼ぶ前に、`git status --short --branch` で今のブランチが plan.md の「ブランチ」欄と同じか確かめ、違えば呼ばずに保留する（ラッパーは今のブランチ（HEAD）を見るので、別のブランチにいると別の変更を確認してしまうため）。worktree のときは、リポジトリの根で打つとメイン側のブランチを見てしまうので、`git -C <パス> fetch origin`・`git -C <パス> status --short --branch` で確かめる
   - `image`：参照画像は `|` 区切りの1つの文字列で渡す
   - `make-patch`：コミットの前の差分を、`/code-review` に渡すパッチのファイルにする（`-Mode make-patch -Task <タスク名> -OutFile <scratchpad のファイル>`。`-PromptFile` は要らない。worktree のときは `-WorkingDirectory` も付ける）。できたら `PATCH: <パッチの絶対パス>` と `FILES: <パッチに入ったファイルの数>` が出る。**終了コード 4 は「見せる差分が無い」**（`-OutFile` は書かれない）。呼んだ側は `/code-review` を呼ばずに保留する。ほかの 0 以外は、秘密情報・設定ファイルの確かめや Git の失敗で止まったこと（パッチは作られない）。数秒で終わる（健さんは呼ばないので、Codex の枠も使わない）
   - `save-code-review`：`/code-review` の結果の文を書いた一時ファイルを渡して保存する（`-Mode save-code-review -Task <タスク名> -Stage <plan|pr|check> -InputFile <ファイル>`。`-Stage` は承認前（計画書）が `plan`、PR の前が `pr`、チェックが2回以上落ちたとき（K2）が `check`。`-PromptFile` は要らない）。保存先は、リポジトリの中なら `docs/tasks/<タスク名>/code-review/<連番>-<Stage>.md`（メインのチェックアウトの下。`.gitignore` で Git に入れない）、Git に無視されていなければ `<一時ディレクトリ>/code-review-replies/<リポジトリのフォルダ名>-<パスから作った8文字>/<タスク名>/`。出てきた `SAVED:` の行の保存先を、承認前は plan.md の「承認前の確認」に、PR の前と K2 は review.md のその回の「返事：」に書く（簡単な修正の道では PR 本文）。保存先が一時ディレクトリ（絶対パス）なら、OS の一時ディレクトリの部分を `<一時ディレクトリ>` と書く（ローカルの絶対パスやユーザー名を記録に残さないため）。中身はそのまま書く（要約しない）。数秒で終わる（健さんは呼ばないので、Codex の枠も使わない）
   - 1回に数分かかる（相談・レビューで5〜7分ほど）。ラッパーはバックグラウンドで回す（Bash ツールの `run_in_background`。workflow.md の言葉の決まり「バックグラウンド」）。終わりの知らせを受けてから結果を読む
4. 一時ファイルを消す
5. 健さんの答えをそのまま採らない。コード・一次データと照らして確かめる（`/code-review` や adversary と同じ扱い）
6. 返すときは「健さんの答え（使えるところ）」と「判断（同意・不同意・残るリスク・次の手）」を分ける
7. 健さんの返事は要約で済ませない。まーちゅうには保存先（ラッパーが出す `SAVED:` の行）を伝え、頼まれたらそのままチャットにも出す
8. PR の前の確認の返事を PR にも貼るときは、秘密情報・クライアント識別情報・ローカルの絶対パスが無いことを確かめてから貼る

## 頼みの文に必ず入れること

- `consult`・`image` の両方
  - 頭に「ガネーシャから」か「メジェドから」（健さんの AGENTS.md は、この頭で請け負う範囲を決める）
  - モードと目的
  - **秘密情報のファイルを開かないこと**。AGENTS.md と同じ決まりで書く
    - 既定の4つ（`.env*`・`.dev.vars`・`.kv/`・`wp-config.php`）
    - 読むリポジトリごとに、その根（git の根）の `.claude/ai-team.json`（無ければ `repo-files/claude/ai-team.json`。テンプレートのリポジトリ）の `secretPatterns` に当たるもの（設定ファイルは読んでよい）。プラグインに切り替える前のリポジトリでは、根の `.claude/hooks/ai-team-config.mjs` の秘密情報の既定の一覧と、根の `.claude/hooks/guard-code-edit.mjs` の `SECRET_PATTERNS` にも当たるもの（フックのファイルも読んでよい）
      - `secretPatterns` はグロブ（`**` は `/` をまたいで0文字以上、`*` は `/` 以外の0文字以上、`?` は `/` 以外の1文字。ほかの文字はそのまま。`**/` は先頭でも途中でも区切りごと省けて0個以上のディレクトリに当たり、最後の `/**` も区切りごと省けて、そのもの自身とその中に当たる。例：`**/.wrangler/**` は、根の直下の `.wrangler` と `.wrangler/state.json` にも、`a/.wrangler/x` にも当たる。`private/**/token.json` は `private/token.json` にも `private/a/b/token.json` にも当たる）で、リポジトリの根からの相対パスに当てる
    - worktree のときは、メインのチェックアウトの根の設定ファイルとフックも合わせて見る
    - 照らし方はフックに従う
  - ファイルを書き換えない・作らないこと
- `consult` だけ
  - 推測せずに、自分でリポジトリを読んでから答えること
  - 答えにファイル:行を付けること。場所はリポジトリの根からの相対パスで書くこと
  - テストは走らせない（read-only で走らないため）。変更に関係するテストがあれば、コードを読んで、壊れそうなテスト・弱められたテストが無いかを見ること
- `image` だけ
  - 作りたい画像の中身（用途・大きさ・背景の透過など）
  - 参照画像の役割（例: 1枚目はキャラクターと画風の参照、2枚目は直前に作った画像で「表情とポーズだけ変える」）
  - 画像は既定の保存先に置いたままにし、**答えの最後の行に `IMAGE_PATH: <保存した画像の絶対パス>` とだけ書くこと**（ラッパーはこの行だけを読む。作業の根が一時ディレクトリなので、相対パスだと解釈の根がずれる）。健さんの AGENTS.md に、この行だけ絶対パスで書く例外があるので、頼みの文に例外を書き足さなくてよい
  - `image` はリポジトリを読まないので、「リポジトリを読む」「ファイル:行」は入れない

`review`（PR の前の確認）は頼みの文を渡せない（対象の指定と頼みの文を同時に受け付けないため）。決まりは健さんの AGENTS.md の「レビューで呼ばれたとき」で持たせている。

## 壊しに来る役を頼むとき

ガネーシャが `consult` で頼む。頼みの文は adversary の定義（プラグインの `agents/adversary.md`）と同じ中身にする。自分の結論や見立ては渡さない（先入観を移さないため）。上限と分かれ目は workflow.md。

- **計画のレビュー**（承認前）
  - 計画書のパス、リポジトリの `docs/team/common-rules.md`、チーム共通の決まり `${CLAUDE_PLUGIN_ROOT}/docs/team-rules.md` と作業の流れ `${CLAUDE_PLUGIN_ROOT}/docs/workflow.md` の場所（スキルとして読み込むと絶対パスになる。健さんは作業の根の外のファイルも読める）
  - 答えの場所の書き方：リポジトリの外のプラグインの文書は `<プラグイン>/docs/workflow.md:NN` の形で書くよう頼む（AGENTS.md の「絶対パスを書かない」と合わせる）
  - 見てほしいこと：外との約束（ほかのリポジトリ・API・データの形・ファイル名）・完了条件の判定・対象外・計画の中の食い違い
  - 報告の形式：指摘ごとに重要度・場所・壊れ方・根拠。見つからなければ1行目に「指摘なし」
  - 「承認前の確認」の節は判断に使わないこと
  - 2回目からは、「改訂履歴の最後の行が前回の指摘で直したところ。直し方が動くかも確かめる」
- **直ったのか隠しただけか**（チェックが2回以上落ちたとき）
  - メジェドの報告の「途中で2回以上落ちたチェック」の行
  - 差分の取り方：`git diff HEAD -- . ":(exclude)docs/tasks/<タスク名>/review.md"` と、未追跡のファイルはディレクトリにまとめず `git status --porcelain -uall` で見ること。worktree のときも `-C` は付けない（健さんはラッパーの `-WorkingDirectory` で worktree を作業の根にして動くため。付けると worktree の中の同じパスを探して失敗する）
  - `docs/tasks/<タスク名>/review.md` は判断に使わないこと
  - 疑う形：テストや期待値の書き換え・条件や対象を外す・例外の握り潰し・スキップ・タイムアウトや再試行で通す

## ラッパーがしてくれること

- `codex` が PATH に無ければ、入れ方を出して止まる（`save-code-review` と `make-patch` を除く。codex に何も渡さないため）
- sandbox は常に `read-only`。`implement` に当たる呼び方（`workspace-write` など）はしない
- 健さんは read-only の sandbox で動くので、一時ディレクトリにも書けず、テストを走らせられない。書ける場所を足す permissions profile も試したが、codex-cli 0.160.0 の Windows の sandbox では、健さんがファイルを読む道具が動かなくなったので使わない（#36）。テストの結果は、メジェドとガネーシャがチェックコマンドで取ったものを使う。健さんには、テストのコードを読ませる（AGENTS.md の決まり）
- 秘密情報の照らし合わせは、ガードと同じ共有モジュール（プラグインの `hooks/ai-team-config.mjs`）を `node` で呼んで行う。既定の4つに、作業の根とメインのチェックアウトの根の `.claude/ai-team.json`（無ければ `repo-files/claude/ai-team.json`。テンプレートのリポジトリ）の `secretPatterns` を足したもの。設定ファイルが壊れていれば（知らないキーやリンク切れも含む）、どのモードでも呼ばずに止まる。`node` が無ければ止まる（どちらも `save-code-review` を除く。codex に何も渡さないため）
- `review`：呼ぶ前に、健さんに渡る変更のすべてのパスを秘密情報のパターンと照らし、1つでも当たれば呼ばずに止まる。見るのは `git status --porcelain -z -uall` のすべての項目（未追跡・ステージ済み・書き換え・名前の変更は元の名前も）と、`-Base` のときは `git diff --name-only --no-renames -z <基準ブランチ>...HEAD` のパス（`--uncommitted` も `--base` も、これらを Codex に送るため）。`-Base` の基準ブランチが無く `git diff` が失敗したときも止まる
- `image`：参照画像を空の一時ディレクトリに `ref-1.png` のような名前でコピーし、そこを作業の根にして呼ぶ（リポジトリには触れない。Codex の `-i` はカンマで値を分けるので、元の名前は渡さない）。答えの `IMAGE_PATH:` の行の画像が、生成画像の保存先（`<CODEX_HOME>/generated_images/`）の下にあり、今回渡した参照画像と別のファイルなら、`IMAGE:` の行で出す。そうでなければ終了コード 2 で止まる（文章から正規表現でパスを探さない。空白・UNC・アポストロフィで取りこぼすため。時刻でも探さない。同時に別の Codex が作った画像を取り違えるため）
- 返事を `docs/tasks/<タスク名>/codex/<連番>-<モード>.md` に保存する（`.gitignore` で Git に入れない）。worktree から呼んでも、保存先は**メインのチェックアウト**（`git worktree list` の1件目）の下になる（写す手順は要らない）。求められなければ作業の根の下。ただし、保存先が `.gitignore` で無視されていないとき（テンプレートを反映していないリポジトリなど）は、リポジトリに未追跡のファイルを残さないため、`<一時ディレクトリ>/codex-replies/<リポジトリのフォルダ名>-<パスから作った8文字>/<タスク名>/` に保存し、`SAVED:` の行は絶対パスになる（標準エラーに知らせも出る）。無視されているかは、実際に保存する名前（`<連番>-<モード>.md`）で `git check-ignore` を打って確かめる。一時ディレクトリに溜まった返事は、手で消してよい（`codex-replies` のフォルダ。溜まっても動きは壊れない）
- `make-patch`：集めるパスと秘密情報・設定ファイルの照らし合わせは `review` と同じ（`git status --porcelain -z -uall`。名前の変更・写したものは元の名前も。ただしサブモジュールの参照の変更も拾うため `--ignore-submodules=none` を付ける。`-Base` は使わない）に、実体のパスの照らし合わせを足したもの（共有モジュールの `check --resolve-real`。パッチにはファイルの中身が入るので、親のディレクトリがジャンクション・シンボリックリンクで実体が秘密情報のもの、実体が作業の根の外のもの、リンク切れも止める）。`docs/tasks/<タスク名>/` は照らす対象には入るが、パッチからは外す。パッチは、`git diff HEAD -M --no-ext-diff --no-textconv --no-color --submodule=short --ignore-submodules=none -- . ":(exclude)docs/tasks/<タスク名>/"`（利用者の Git の設定に左右されないよう、設定に関わるオプションをはっきり付ける。消した行も入る）に、`git ls-files --others --exclude-standard -z` で出た未追跡のファイルの `git diff --no-index`（インデックスは触らない）をつなげたもの。`git diff HEAD`・`git ls-files` の失敗、未追跡の項目がふつうのファイルでないとき（入れ子のリポジトリなど）は終了コード 1 で止まる（「差分が無い」とは扱わない）。UTF-8（BOM なし）で `-OutFile` に書く

## 注意

- 呼ぶたびに、契約しているプランの Codex の枠を使う（相談・レビュー1回で、5時間枠の数%ほど）。1回の依頼は1つにまとめ、同じことを何度も頼まない
- `read-only` は書き込まないだけで、読むのは止めない。秘密情報は、頼みの文と健さんの AGENTS.md で「開かない」と縛ることしかできない（柵であって壁ではない）。AGENTS.md は、既定の4つに加えて、読むリポジトリの根の設定ファイルの `secretPatterns` とフックの `SECRET_PATTERNS` も見る決まり。ただし `review` は組み込みのレビューの頼みの文で動くので、AGENTS.md が守られるとは限らない
- 健さんの AGENTS.md が無い PC では、健さんとして振る舞わない（請け負う範囲の決まりも効かない）。使う前に置いてあるか確かめる
- 健さんの PR の前の確認（`review`）の返事を PR に貼るとき、テストを走らせていないことの注記は要らない（決まりで走らせないため）。テストの結果は PR の「確認」にチェックコマンドの結果として書く
