# codex（健さんに頼む）

健さんは、チームに外から入っている外部委託業者（Codex CLI）。頼めるのは次の3つだけで、**実装は頼まない**（実装はメジェドの担当。健さんがファイルを書き換えると、フックも計画の承認も通らないため）。

| モード | 中身 | 使う人 |
| --- | --- | --- |
| `consult` | 読むだけの相談。既定のモード | ガネーシャ・メジェド |
| `review` | 読むだけのレビュー（未コミットの変更、または基準ブランチとの差分） | ガネーシャ |
| `image` | 参照画像を渡して、画像を1枚作る。できた画像はリポジトリに置かない（置くのはメジェド） | メジェド |

adversary はこのスキルを使わない。

健さんの設定（キャラ・請け負う範囲）は、各 PC の `<CODEX_HOME>/AGENTS.md`（既定は `~/.codex/AGENTS.md`）にある。見本はテンプレートの `repo-files/codex/AGENTS.md`。

## 手順

1. 依頼を、健さんが1回で答えられる1つの頼みにする。会話の経緯をそのまま渡さない
2. 頼みの文を一時ファイルに書く。置き場所はセッションの scratchpad（`<一時ディレクトリ>/claude/` の下。フックが編集を通すのはここだけ）。`review` は頼みの文を使わない
3. リポジトリの根から、Bash ツールで次の文字列で呼ぶ（allow に入っているのはこの形だけ）

   ```
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File .claude/skills/codex/scripts/invoke-codex.ps1 -Mode <consult|review|image> -Task <タスク名> [-PromptFile <一時ファイル>] [-Image "<画像1>|<画像2>"] [-Base <基準ブランチ>]
   ```

   - `-Task` は必須（返事を `docs/tasks/<タスク名>/codex/` に残すため。無ければラッパーが止まる）
   - `review`：コミット前は何も付けない（`--uncommitted`）。コミット済みを見るときは `-Base <既定ブランチ>`
   - `image`：参照画像は `|` 区切りの1つの文字列で渡す
   - 1回に数分かかる（相談・レビューで5〜7分ほど）。Bash ツールのタイムアウトは長めにする
4. 一時ファイルを消す
5. 健さんの答えをそのまま採らない。コード・一次データと照らして確かめる（`/code-review` や adversary と同じ扱い）
6. 返すときは「健さんの答え（使えるところ）」と「判断（同意・不同意・残るリスク・次の手）」を分ける
7. 健さんの返事は要約で済ませない。まーちゅうには保存先（ラッパーが出す `SAVED:` の行）を伝え、頼まれたらそのままチャットにも出す
8. PR の前の確認の返事を PR にも貼るときは、秘密情報・クライアント識別情報・ローカルの絶対パスが無いことを確かめてから貼る

## 頼みの文に必ず入れること

- `consult`・`image` の両方
  - 頭に「ガネーシャから」か「メジェドから」（健さんの AGENTS.md は、この頭で請け負う範囲を決める）
  - モードと目的
  - **秘密情報のファイルを開かないこと**（`.env*`・`.dev.vars`・`.kv/`・`wp-config.php` など。リポジトリの `guard-code-edit.mjs` の `SECRET_PATTERNS` と同じ一覧）
  - ファイルを書き換えない・作らないこと
- `consult` だけ
  - 推測せずに、自分でリポジトリを読んでから答えること
  - 答えにファイル:行を付けること。場所はリポジトリの根からの相対パスで書くこと
- `image` だけ
  - 作りたい画像の中身（用途・大きさ・背景の透過など）
  - 参照画像の役割（例: 1枚目はキャラクターと画風の参照、2枚目は直前に作った画像で「表情とポーズだけ変える」）
  - 画像は既定の保存先に置いたままにし、**答えの最後の行に `IMAGE_PATH: <保存した画像の絶対パス>` とだけ書くこと**（ラッパーはこの行だけを読む。作業の根が一時ディレクトリなので、相対パスだと解釈の根がずれる）
  - `image` はリポジトリを読まないので、「リポジトリを読む」「ファイル:行」は入れない

`review` は頼みの文を渡せない（対象の指定と頼みの文を同時に受け付けないため）。決まりは健さんの AGENTS.md の「レビューで呼ばれたとき」で持たせている。

## ラッパーがしてくれること

- `codex` が PATH に無ければ、入れ方を出して止まる
- sandbox は常に `read-only`。`implement` に当たる呼び方（`workspace-write` など）はしない
- `review`：呼ぶ前に `git status --porcelain -z -uall` を見て、未追跡の秘密情報のファイルがあれば呼ばずに止まる（`--uncommitted` は未追跡のファイルを Codex に送るため）
- `image`：参照画像を空の一時ディレクトリに `ref-1.png` のような名前でコピーし、そこを作業の根にして呼ぶ（リポジトリには触れない。Codex の `-i` はカンマで値を分けるので、元の名前は渡さない）。答えの `IMAGE_PATH:` の行の画像が、生成画像の保存先（`<CODEX_HOME>/generated_images/`）の下にあり、今回渡した参照画像と別のファイルなら、`IMAGE:` の行で出す。そうでなければ終了コード 2 で止まる（文章から正規表現でパスを探さない。空白・UNC・アポストロフィで取りこぼすため。時刻でも探さない。同時に別の Codex が作った画像を取り違えるため）
- 返事を `docs/tasks/<タスク名>/codex/<連番>-<モード>.md` に保存する（`.gitignore` で Git に入れない）

## 注意

- 呼ぶたびに、契約しているプランの Codex の枠を使う（相談・レビュー1回で、5時間枠の数%ほど）。1回の依頼は1つにまとめ、同じことを何度も頼まない
- `read-only` は書き込まないだけで、読むのは止めない。秘密情報は、頼みの文と健さんの AGENTS.md で「開かない」と縛ることしかできない（柵であって壁ではない）
- 健さんの AGENTS.md が無い PC では、健さんとして振る舞わない（請け負う範囲の決まりも効かない）。使う前に置いてあるか確かめる
