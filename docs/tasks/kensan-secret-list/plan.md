## 目的

健さん（Codex）が開かない秘密情報の一覧に、リポジトリごとに足したパターン（例: swx-inventory-hub の `.wrangler/`）が入るようにする。AGENTS.md はリポジトリをまたぐ1枚なので、リポジトリ固有の名前は書かず、「読むリポジトリのフックの `SECRET_PATTERNS` に当たるもの」を開かない、と書く。

## 背景・前提

- 健さんの決まりは、各 PC の `<CODEX_HOME>/AGENTS.md`（見本はテンプレートの `repo-files/codex/AGENTS.md`）にある。秘密情報の一覧は2か所：「ガネーシャ・メジェドから頼まれたとき」（26行目）と「レビュー（`codex exec review`）で呼ばれたとき」（37行目）。どちらも既定の4つ（`.env*`・`.dev.vars`・`.kv/`・`wp-config.php`）に「など」を付けた形。既定の4つは、テンプレートのフックの `SECRET_PATTERNS` の既定と同じ
- `consult`・`image` は頼みの文に一覧を書く（codex の SKILL.md の「頼みの文に必ず入れること」。「リポジトリの `guard-code-edit.mjs` の `SECRET_PATTERNS` と同じ一覧」）。`review` は頼みの文を渡せないので、AGENTS.md の決まりだけになる
- `review` の sandbox は `read-only` で、読むことは止めない（SKILL.md の「注意」）。ラッパーの `review` の前の確かめ（#14）は「健さんに渡る変更」だけを見るので、`.gitignore` で無視された `.wrangler/` を健さんが開くことは縛れない
- **`review` で AGENTS.md が守られるとは限らない。** `review` は Codex 組み込みのレビューの頼みの文で動き、AGENTS.md の「相対パスで書く」が守られなかった回がある（このリポジトリの `docs/tasks/codex-skill/review.md` の記録）。守られた回もある。だからこのタスクは「決まりを健さんの読む文書に置く」までで、開かないことを保証するものではない（柵であって壁ではない。SKILL.md の「注意」と同じ立場）
- 健さんは、作業の根の外のリポジトリも読むことがある（テンプレートと反映先を見比べる相談など）。だから「作業の根のフック」ではなく、**読むリポジトリごとに、その根（git の根）のフック**を見る形にする。作業の根が呼んだ場所次第（ラッパーの `-WorkingDirectory` を省くと呼んだときのディレクトリ）でも、リポジトリの根で数えれば同じになる
- フックの置き場所は、反映したリポジトリでは `.claude/hooks/guard-code-edit.mjs`、テンプレート置き場（このリポジトリ）では `claude/hooks/guard-code-edit.mjs`
- hub では `.wrangler/` を、フック・ラッパー・settings.json の `Read` の deny・common-rules にそろえた（hub PR #93）。健さんの AGENTS.md だけ無い
- まーちゅうの決定（2026-10-06）：AGENTS.md には hub 固有の名前を書かず、フックの `SECRET_PATTERNS` を見る形にする。既定の4つは、フックが無いリポジトリのために残す
- フックのファイル（`guard-code-edit.mjs`）は秘密情報ではない（`SECRET_PATTERNS` に当たらない）。健さんが読んでよい
- README で「パターンを足すとき」の説明は2か所にあり、足す場所の一覧が違う：「導入方法」の4（フックとラッパー）と「導入後に確認すること」の「秘密情報」（フックと settings.json の `Read` の deny）。hub で実際にそろえたのは、フック・ラッパー・settings.json の `Read` の deny・common-rules の4か所

## 変更内容

### 書く中身（言い回しはメジェドに任せる。意味はこのとおり）

- AGENTS.md の2か所とも、同じ条件で書く
  - 開かないもの：既定の4つ（`.env*`・`.dev.vars`・`.kv/`・`wp-config.php`）と、**読むリポジトリごとに、その根（git の根）の `.claude/hooks/guard-code-edit.mjs`（無ければ `claude/hooks/guard-code-edit.mjs`）の `SECRET_PATTERNS` に当たるもの**。作業の根の外のリポジトリを読むときも、そのリポジトリの根のフックで判断する。**worktree のときは、その worktree の根のフックに加えて、メインのチェックアウト（`git worktree list` の1件目）の根のフックも見て、両方の一覧を合わせたものを開かない**（フックを入れる前の版で切った worktree には、フックが無いため）
  - 照らし方は**フック（`guard-code-edit.mjs` の照らす前のそろえ方と、実体のパスの判定）にそのまま従う**（AGENTS.md には、フックの照らし方に従う、と書く。下は今のフックの照らし方で、例として添える）：OS の区切り文字（Windows なら `\`）を `/` にそろえ、Windows のときだけ大文字を小文字にそろえてから照らす。見たままのパスと、親ディレクトリも含めてリンクをたどった実体のパスの両方に照らし、どちらかで当たれば開かない
  - フックのファイルは読んでよい（一覧を知るため）。見る場所のどこにも無ければ既定の4つだけ
  - 「ガネーシャ・メジェドから頼まれたとき」は、さらに依頼の文に書かれたもの（今の「依頼の文に書かれたもの」を残す）
  - 既定の4つ以外のパターン名（`.wrangler/` など）は書かない
- SKILL.md の「頼みの文に必ず入れること」の秘密情報の箇条：AGENTS.md と同じ決まりにする（「リポジトリのフックと同じ一覧」の言い方をやめる。条件を2か所で分けないため）
- SKILL.md の「注意」：上の決まりを一言で書き、`review` は組み込みのレビューの頼みの文で動くので AGENTS.md が守られるとは限らない（柵であって壁ではない）と書く
- README の2か所：パターンを足すときにそろえる場所を「フックの `SECRET_PATTERNS`・ラッパーの `$SecretPatterns`・settings.json の `Read(...)` の deny・common-rules.md の秘密情報の箇条」と同じ並びで書き、健さんの AGENTS.md は読むリポジトリのフックを見るので直さなくてよい、と書く
