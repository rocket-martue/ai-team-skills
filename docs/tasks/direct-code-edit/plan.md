## 目的

簡単な修正の道に、直すことがもう分かっている小さなコードの直し（値の差し替え・テストの期待値をそろえる、など数行のもの）を足す。まーちゅうがメッセージで決まった言い方（「ガネーシャが直接コード書いて」など）で指示したときだけ、ガネーシャが Edit / Write でコードを直せるようにし、PR の前のレビューは1回だけにする。

## 変更内容

### 1. 印のフック（`direct-edit-mark.mjs`）

- UserPromptSubmit で、入力の `prompt` を見る
  - まず、まーちゅう以外が送ったと分かる書き出しかを見る。`prompt` の頭の空白を除いた先頭が次のどれかなら、印を付けない（消す言い方は見る。消す方は安全側なので）
    - `Another Claude session sent a message`・`<agent-message`・`<task-notification`・`<system-reminder`
  - 空白（半角・全角・改行）を除いた文に、付ける言い方のどれかが入っていたら、そのセッションの印を付ける（あれば付け直して時刻を新しくする）
    - 付ける言い方：「ガネーシャが直接コード書いて」「ガネーシャが直接直して」
  - 消す言い方が入っていたら、そのセッションの印を消す。付ける言い方と両方入っていたら、消す方を取る
    - 消す言い方：「直接書くのはおしまい」
  - 付けた・消したときだけ、`additionalContext` でガネーシャに伝える（付けた：印を付けたこと・範囲と流れは workflow.md の簡単な修正の道・消す言い方。消した：印を消したこと）。どちらにも当たらないときは何も出さない
  - 消せなかったとき（ファイルが消えずに残った。消した後に、まだあるかを確かめて判定する）は、`additionalContext` で「印を消せなかった。ガネーシャはコードを直さない」と伝える
  - そのほか：ほかのセッションの、24時間より古い印を消す
- SessionEnd で、そのセッションの印を消す（1.5秒の中で終わるよう、消すだけにする）
- SessionStart（matcher は `resume`。再開したとき）で、そのセッションの印を消す（SessionEnd が動かずに終わったセッションを再開したときに、印を残さないため。消せなかったときは、`additionalContext` で消せなかったと伝える）
- 印を作る・付け直す・消す・掃除するときは、リンクをたどらない（編集のガードは、フック自身のファイル操作には効かないため）
  - 置き場所のディレクトリ（`ai-team-direct-edit`）がシンボリックリンク（ジャンクションを含む）なら、何もしない（消すときは、消せなかったと伝える）。無ければ作る
  - 印を付ける・付け直すときは、同じディレクトリに別の名前で新しく作ってから（既にあれば作らない書き方で）、印の名前に置き換える（印の名前がリンクでも、リンク先に書かない）
  - 消すときは、印の名前そのものを消す（リンクなら、リンクだけが消え、リンク先は残る）
- どの場合も終了コード 0 で終わり、まーちゅうのメッセージを止めない（入力が読めない・印が書けないときも。印を付けられなかったときは、付けたと伝えない）
- `session_id` が英数字・`-`・`_` だけの1〜128文字でなければ、印を付けない・消さない（ファイル名に使うため）

### 2. 印の置き場所と読み方（`ai-team-config.mjs`）

- 置き場所：`<一時ディレクトリ>/ai-team-direct-edit/<session_id>`
  - `<一時ディレクトリ>/claude/`（ガードがガネーシャの Edit / Write を通す scratchpad）の外にする
  - リポジトリを一時ディレクトリやその上（ホームなど）で開いたときは、置き場所がリポジトリの中に入り、メジェドの行 8 で書けてしまう。そのため、ガードは置き場所（`<一時ディレクトリ>/ai-team-direct-edit/` とその下。指定されたパスと実体のパスの両方）への編集を、誰が・どこで開いていても止める（変更内容3）
- 中身：JSON で `{"createdAt": <付けた時刻。1970年からのミリ秒の整数>}`
- 印の状態は3つ
  - 有効：ふつうのファイルで、`createdAt` が有限の整数で、今から24時間以内（未来の時刻は、5分先までは今と同じに扱い、それより先は壊れているとする）
  - 切れた：ふつうのファイルで、`createdAt` が24時間より古い
  - 無い：ファイルが無い・読めない・JSON でない・`createdAt` が整数でない・5分より先の時刻・印のファイルか置き場所のディレクトリがシンボリックリンク（ジャンクションを含む）・印のファイルのハードリンクが2つ以上あるとき
- 置き場所と読み方は、フックとガードで同じ部品を使う（ずれないように）

### 3. ガード（`guard-code-edit.mjs`）

- 印の置き場所（`<一時ディレクトリ>/ai-team-direct-edit/` とその下）への編集は、誰でも止める（×）。判定の最初（設定ファイル自体の確認より前）に、指定されたパスと実体のパスの両方に当てる。これは、メジェドとほかのサブエージェントの判定を変えない、の例外（印を作れないようにするため）
- メインのエージェント（`agent_id` が無い）で、入力の `session_id` の印が有効なときだけ、行 8（コード）を通す
- 行 1〜7 の判定は変えない（秘密情報・リポジトリの外は×、`.claude/`・`docs/team/`・根の `CLAUDE.md`・設定ファイルは確認のまま）
- サブエージェント（メジェド以外）は、印があっても今のまま（行 8 は×）
- 止める理由の文
  - 印が無いとき：今のまま（まーちゅうが指示したときだけ直せることは書かない。ガネーシャが言い出すきっかけにしないため）
  - そのセッションの印が切れたとき：まーちゅうの指示の印が24時間で切れたこと、を足す（まーちゅうが付け直せるように）

### 4. 作業の流れ（`workflow.md` の「簡単な修正の道」）

- 範囲に「まーちゅうの指示があったときの小さなコードの直し」を足す
  - 小さな：直すことがもう分かっていて、`origin/<既定ブランチ>` と作業ツリーの差分（未コミットを含む）が3ファイル以内・追加と削除の行の合計が20行以内（`git diff --numstat origin/<既定ブランチ>` で数える）。直した後とレビューの指摘を直した後の、両方で数える。超えたら範囲の外（手順4と同じく保留する）
  - 入れないもの：今の「入れないもの」から「コード」を外す（指示があるときの、この直しに限る。指示が無いときは今までどおりコードは入れない）。そのうえで、新しい関数・クラス・ファイルの追加、依存の追加・更新、秘密情報に触れるものを足す
- 入り方：まーちゅうのメッセージに付ける言い方があったときだけ（印のフックが付けた印で、ガードが通す）。指示が、この道に入る OK とブランチを切る OK を兼ねる。ガネーシャは、直すファイル・ブランチ名・PR の前のレビュー役を伝えてから進める（聞き直さない）。範囲に入らないと分かったら、直さずにそう伝える。ガネーシャから、この道で直すことを言い出さない
- PR の前のレビュー役：まーちゅうが指示と一緒に「健さんで」「/code-review で」と言える。言わなければ健さん。`/code-review` のレベルは、言わなければ `high`
- レビューは1回だけ（今の「採る指摘が0になるまで最大5回」は、この直しには使わない）。採る指摘が範囲の中なら、ガネーシャが直してチェックコマンドを全部通し、頼み直さずに報告へ進む（直したことは PR 本文に書く）。範囲の外が要るなら、今の手順4と同じく保留する
- PR の後の Fさんは回さない
- PR に付いたレビュー（人・bot）は今の簡単な修正の道と同じ。ただし、コードの指摘を直すのに、そのセッションに印が無いときは、ガネーシャは「印が無いので直せない」とだけ伝えて止まる（この道で作った PR の続きなので、言い出しには当たらない）。まーちゅうが付ける言い方を言ったら直す
