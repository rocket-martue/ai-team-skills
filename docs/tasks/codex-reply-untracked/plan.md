## 目的

健さんのラッパー（`invoke-codex.ps1`）が、返事の保存先（`docs/tasks/<タスク名>/codex/`）が Git に無視されていないリポジトリから呼ばれたときに、そのリポジトリに未追跡のファイルを残さないようにする。無視されていないときは、OS の一時ディレクトリの下に保存し、そのパスを `SAVED:` の行で出す（#35 の案B）。

## 背景・前提

- ラッパーは返事を `<保存先の根>/docs/tasks/<タスク名>/codex/<連番>-<モード>.md` に書く（`claude/skills/codex/scripts/invoke-codex.ps1:191-212` の `Save-Reply`）。保存先の根は、worktree から呼んでもメインのチェックアウト（`git worktree list` の1件目）。求められなければ作業の根（同 `:167-189` の `Get-ReplyRoot`）
- `SAVED:` の行は、リポジトリの根からの相対パス（`docs/tasks/<タスク名>/codex/<名前>`）で出している（同 `:209`・`:278`）
- 反映したリポジトリでは、`.gitignore` に `repo-files/gitignore.snippet` の `docs/tasks/*/codex/` が入っていて、返事は Git に入らない。反映していないリポジトリ（設計ドキュメント専用で `docs/tasks/` を持たないものなど）では、未追跡のファイル（`?? docs/`）として残る（#35）
- 案の比較（#35）：A（保存せず標準出力だけ）は、スキルの「返事は要約で済ませず保存先を伝える」（`claude/skills/codex/SKILL.md` の手順7）が守れない。C（保存先を引数で渡す）は、渡し忘れると同じことが起きる。B（一時ディレクトリに保存）なら、呼ぶ側が何もしなくても、反映していないリポジトリで安全になる
- 今のテスト（`claude/skills/codex/scripts/test-invoke-codex.mjs`）の偽物の codex は、呼ばれた印を書くだけで、`-o` の返事のファイルを書かない。だから今のテストは、保存のところ（`Save-Reply`）まで一度も通っていない（ラッパーは「返事が取れませんでした」で止まる）
- このリポジトリのチェックコマンド（このタスクに限る）：`node claude/hooks/test-guard-code-edit.mjs` と `node claude/skills/codex/scripts/test-invoke-codex.mjs`

### テスト（`test-invoke-codex.mjs`）

- 偽物の codex を、引数の `-o` の次の値のファイルに返事（例：`fake reply`）を書いてから、呼ばれた印を書いて終了コード 0 で終わるものにする。ラッパー（Windows PowerShell 5.1）の `& codex` は、PATHEXT の順にかかわらず `codex.ps1` を選ぶので、`-o` の処理は**`codex.ps1` に入れる**（`codex.cmd` にも同じ動きを入れてそろえる）。今の12本の判定（呼ばれたか・止まったか）は変えない

- 足すテスト（どれも review モード・偽物の codex）
  1. `.gitignore` に `docs/tasks/*/codex/` があるリポジトリ：ラッパーが終了コード 0 で、`SAVED: docs/tasks/t/codex/01-review.md` を出し、そのファイルがリポジトリの中にあり、中身が偽物の返事。`git status --porcelain` に `docs/` の行が出ない
  2. `.gitignore` に無いリポジトリ：ラッパーが終了コード 0 で、`SAVED:` の行が `<テストの TEMP>` の下の絶対パスで、そのファイルがあり、中身が偽物の返事。リポジトリに `docs/` が作られていない（`git status --porcelain` が呼ぶ前と同じ）。標準エラーに「一時ディレクトリに保存しました」が出ている
  4. `.gitignore` に `docs/tasks/*/codex/*` と `!docs/tasks/*/codex/*-review.md` があるリポジトリ（仮の名前は無視されるが、review の返事の名前は無視されない）：返事が一時ディレクトリに保存され、リポジトリの `git status --porcelain` が呼ぶ前と同じ
  5. Git のリポジトリでないディレクトリから **image モード**で呼ぶ（review・consult は、保存の前に git や codex がリポジトリを求めて止まるので、ここに届くのは image だけ）：`-Image` に小さな画像を1枚渡し、偽物の codex は返事に `IMAGE_PATH:` の行を書かない。ラッパーは終了コード 2 で止まるが、その前に `SAVED:` の行で `<テストの TEMP>` の下の絶対パスを出し、そのファイルがある。呼んだディレクトリに `docs/` が作られていない
  6. 親が違う同じ名前のリポジトリ2つ（例：`<root>/a/same` と `<root>/b/same`。どちらも `.gitignore` に行が無い）から同じタスク名で呼ぶと、`SAVED:` の行のディレクトリが別々で、どちらも `01-review.md`
  7. worktree から呼ぶ：メインのチェックアウトの `.gitignore` には行が無く、worktree のブランチでは `.gitignore` に行を足してコミットしてある。`-WorkingDirectory` に worktree を渡して呼ぶと、無視されているかはメインのチェックアウトで判定され、返事は一時ディレクトリに保存される。メインのチェックアウトにも worktree にも、未追跡のファイルが増えない
  3. 2と同じリポジトリでもう一度呼ぶと、`SAVED:` の行が `<テストの TEMP>` の下の `02-review.md` の絶対パスになり、そのファイルがあり、標準エラーに知らせが出て、リポジトリの `git status --porcelain` が呼ぶ前と同じ（連番が一時ディレクトリでも続く）
