## 背景・前提

- まーちゅうが持っているサンプルのスキル（`/codex consult|review|implement` で `codex exec` を呼ぶ PowerShell のラッパー）を元にする。#3 の「サンプルのスキルのままでは、うちの体制とぶつかるところ」の5つを直す
- `codex exec --help` と `codex exec review --help`（0.160.0）で確かめたこと
  - `codex exec`：`-C <ディレクトリ>`（作業の根）、`-i <画像>...`（複数の値を取る）、`-s read-only|workspace-write|danger-full-access`、`--ephemeral`、`-o <ファイル>`（最後の返事）、`--color never`。頼みの文は、引数が無ければ標準入力から読む
  - `codex exec review`：`--uncommitted`（ステージ済み・未ステージ・**未追跡**の変更）、`--base <ブランチ>`、`--commit <SHA>`、`-o`。**対象の指定（`--uncommitted`・`--base`・`--commit`）と頼みの文（カスタムの指示）は同時に渡せない**（`error: the argument '--uncommitted' cannot be used with '[PROMPT]'`。実際に打って確かめた）。**`-s`・`-C`・`--color`・`-i` は無い**ので、sandbox は `-c sandbox_mode="read-only"` で渡し、作業の根はラッパーが移動してから呼ぶ
- Claude Code の権限規則は、Bash ツールと PowerShell ツールで別物（`Bash(...)` は PowerShell ツールの呼び出しに当たらない）で、コマンドの文字列で一致を見る（公式ドキュメント permissions・tools-reference）。メジェドの tools は Bash だけ
- PATH の `codex` は npm の `.ps1` のシムなので、実行ポリシーが既定（Restricted）の PC では止まる。ラッパーを `-ExecutionPolicy Bypass` 付きで起動すれば、同じプロセスの中で呼ぶ `codex` にも効く
- 画像生成は、Codex に同梱のシステムスキル `imagegen` が、組み込みツール `image_gen` を使う（`OPENAI_API_KEY` 不要）。保存先は `<CODEX_HOME>/generated_images/<スレッド>/` の下（`CODEX_HOME` を設定していなければ `~/.codex`。環境変数としては空のことがある）。`codex exec` から画像生成が動くか、読むだけの sandbox で動くかは、まだ確かめていない
- Codex の呼び出しは、契約しているプランの Codex の枠を使う
- テンプレートのリポジトリにはフックもメジェドも `.claude/` も無いので、このタスクの実装はガネーシャが行い、確かめられるのはラッパーを直接打つところまで（スキル・allow・メジェドとして動くかは、反映先で確かめる）

## 変更内容

### SKILL.md の中身

- frontmatter：`name: codex`、description（「健さんに聞いて」「Codex に聞いて」「Codex にレビューさせて」「セカンドオピニオン」「画像を作って」などで使う。実装は頼まない）、`argument-hint: "[consult|review|image] <依頼>"`
- モード
  - `consult`：読むだけの相談。既定のモード
  - `review`：読むだけのレビュー。未コミットなら `--uncommitted`、コミット済みなら `--base <既定ブランチ>`
  - `image`：画像の生成。参照画像を渡せる。できた画像はリポジトリに置かない（置くのはメジェド）
  - `implement` は**無い**。健さんがファイルを書き換えると、フックも計画の承認も通らないため
- 手順
  1. 依頼を、健さんがリポジトリを読んで答えられる1つの頼みにする（会話の経緯をそのまま渡さない）
  2. 頼みの文を一時ファイルに書く。置き場所はセッションの scratchpad（`<一時ディレクトリ>/claude/` の下。フックが編集を通すのはここだけのため）
  3. Bash ツールから、下の「呼び方の文字列」でラッパーを呼ぶ
  4. 一時ファイルを消す
  5. 健さんの答えをそのまま採らない。コード・一次データと照らして確かめる
  6. 返すときは「健さんの答え（使えるところ）」と「ガネーシャの判断（同意・不同意・残るリスク・次の手）」を分ける
  7. 健さんの返事は要約で済ませない。まーちゅうには保存先（`docs/tasks/<タスク名>/codex/`）を伝え、頼まれたらそのままチャットにも出す
  8. PR の前の確認（次のタスクで adversary を健さんに替えた後）の返事は、PR があれば、秘密情報・クライアント識別情報・ローカルの絶対パスが無いことを確かめてから、PR にもコメントで貼る（Copilot のレビューと同じく、GitHub で読めるようにするため）
- 頼みの文に必ず入れること（`consult`・`image`。`review` は頼みの文を渡せないので、健さんの AGENTS.md の「レビューで呼ばれたとき」で縛る）：
  - 両方：頭に「ガネーシャから」か「メジェドから」、モード、目的、**秘密情報のファイルを開かないこと**（各リポジトリの `guard-code-edit.mjs` の `SECRET_PATTERNS` と同じ一覧）、ファイルを書き換えないこと
  - `consult` だけ：推測させず自分でリポジトリを読ませること、答えにファイル:行を付けること（場所はリポジトリの根からの相対パス）
  - `image` だけ：作りたい画像の中身、参照画像の役割（キャラクターや画風をそろえる・表情とポーズだけ変える、など）、画像は既定の保存先に置いたままにすること、答えの最後の行に `IMAGE_PATH: <保存した画像の絶対パス>` とだけ書くこと（作業の根が一時ディレクトリなので、相対パスだと解釈の根がずれる。`image` はリポジトリを読まないので、「リポジトリを読む」「ファイル:行」「相対パス」は入れない）
- 誰が使うか：ガネーシャは `consult`・`review`。メジェドは `consult`・`image`。adversary は使わない
- 呼び方の文字列（ガネーシャもメジェドも、リポジトリの根から Bash ツールで）：`powershell.exe -NoProfile -ExecutionPolicy Bypass -File .claude/skills/codex/scripts/invoke-codex.ps1 -Mode <モード> -Task <タスク名> -PromptFile <一時ファイル> ...`（`-Task` は必須）

### invoke-codex.ps1 の中身

- 引数：`-Mode consult|review|image`、`-PromptFile`、`-WorkingDirectory`（省略時は今のディレクトリ）、`-Image`（`image` の参照画像。複数は `|` 区切りの1つの文字列で受け、ラッパーの中で分ける。Bash から `powershell.exe -File` に配列を渡すと崩れるため。`|` は Windows のパスに使えない文字なので、パスの中身と混ざらない。さらに、Codex の `-i` 自体が値をカンマで分けるので、ラッパーは参照画像を空の一時ディレクトリに `ref-1.png` のような安全な名前でコピーし、そのディレクトリに移動してから `-i ref-1.png` のように名前だけを渡す。親のパスにカンマがあっても混ざらない）、`-Base`（`review` でコミット済みを見るときの基準ブランチ）、`-Task`（返事を保存するタスク名。必須）
- 共通：`codex` が PATH に無ければ、入れ方（`npm install -g @openai/codex` と `codex login`）を出して止まる。頼みの文は UTF-8（BOM なし）で標準入力に渡す。`-` は付けない（`-i` が複数の値を取るので、引数の解釈がずれないようにする）。答えは `-o` の一時ファイルから読んで標準出力に出す。あわせて、答えをそのまま `docs/tasks/<タスク名>/codex/<連番>-<モード>.md` に保存する（`-Task` 引数でタスク名を受ける。`-Task` が無ければ、呼ばずに止める）。保存先のフォルダは `.gitignore` で Git に入れない（まーちゅうが VS Code で健さんの返事を読めるようにするため）
- `consult`：`codex exec --ephemeral --color never -s read-only -C <dir> -o <一時ファイル>`
- `review`
  - 呼ぶ前に、作業の根で `git status --porcelain -z -uall` を見て（`-uall` が無いと未追跡のディレクトリが1行にまとまり、中のファイルを見落とすため。`-z` が無いと空白や日本語を含むパスが引用符付きで出て、パターンに当たらないため）、未追跡（`??`）のファイルに秘密情報のパターン（`SECRET_PATTERNS` と同じ）に当たるものがあれば、呼ばずに止める（`--uncommitted` は未追跡のファイルを Codex が自分で拾い、頼みの文では止められないため）
  - 作業の根に移動してから `codex exec review --uncommitted -c sandbox_mode="read-only" -o <一時ファイル>`（`-Base` があれば `--uncommitted` の代わりに `--base <Base>`）。頼みの文は渡さない（`-PromptFile` は `review` では使わない）
- `image`
  - **作業の根は、リポジトリではなく空の一時ディレクトリにする**（scratchpad の下に作る）。参照画像はこのディレクトリにコピーして `-i` で渡すので、リポジトリを読む必要が無い。健さんがリポジトリを書き換える道が無くなる。Git のリポジトリではないので `--skip-git-repo-check` を付ける
  - 空の一時ディレクトリに移動してから `codex exec --ephemeral --color never --skip-git-repo-check -s read-only -C . -o <一時ファイル> -i ref-1.png -i ref-2.png ...`
  - **sandbox は `read-only` だけ。** 読むだけで画像が作れなかったら、`workspace-write` に切り替えずに止めて報告する（書き込みの道を残すと、ユーザー設定の書き込み先や一時領域の扱いなど、設定の穴を追い続けることになるため）
  - 終わったら、健さんの答えの `IMAGE_PATH:` の行だけを読み、その画像が生成画像の保存先の下にあり、今回渡した参照画像（元のファイル）と別なら出す（文章から正規表現でパスを探さない）。パスが無い、またはそのファイルが無ければ、パスを出さずに止める（時刻で探すと、同時に別の Codex が作った画像を取り違えるため。探さない）
  - 空の一時ディレクトリは、終わったら消す
- 使わない引数：`--dangerously-bypass-approvals-and-sandbox`・`danger-full-access`・`--approve-for-me`

### 権限（settings.json）

- allow に足すのは `Bash(powershell.exe -NoProfile -ExecutionPolicy Bypass -File .claude/skills/codex/scripts/invoke-codex.ps1:*)` だけ（上の呼び方の文字列と同じ先頭）
- `powershell.exe` の任意のコマンド、PowerShell ツールの規則、`codex` そのものは足さない（ラッパーを通さない呼び方を防ぐため）
- allow はサブエージェント全員に効くので、adversary も確認なしでラッパーを呼べてしまう。adversary.md の禁止事項で縛る（次のタスクで呼び先を替えるまで）

### 画像の置き方（mejed.md）

- メジェドが `image` で作った画像は、ラッパーが出したパスから、plan.md に書かれた置き場所へコピーする。ラッパーがパスを出さずに止まったら、コピーせずに報告する。既存のファイルは上書きしない（別の名前にする）
- 参照画像（キャラクターのスタイルガイドや、1枚目の画像）は `-Image` で渡す。キャラクターをそろえたいときは、1枚目ができたらそれを2枚目以降の参照にする

### データの流れ

- ガネーシャ／メジェド → 頼みの文（一時ファイル）→ ラッパー → `codex`（健さん）→ 答え（一時ファイル）→ ラッパーの標準出力と `docs/tasks/<タスク名>/codex/`（まーちゅうも読める）→ ガネーシャ／メジェドが確かめる
- `image` のときは、画像が `<CODEX_HOME>/generated_images/<スレッド>/` にでき、ラッパーがパスを出し、メジェドがリポジトリにコピーする

## 方針
