- `codex exec review --uncommitted` は、ステージ済み・未ステージ・未追跡の変更を健さんに渡す。`--base <ブランチ>` は、そのブランチとの差分を渡す。だから次の場合に、秘密情報の中身が送られうる
  - 秘密情報のファイルをステージした（`A `）・追跡していて書き換えた（`M`・` M`）・名前を変えた（`R`。元の名前か新しい名前が秘密情報）

- `git status --porcelain -z` の形：各項目は `XY <パス>`。名前を変えた・写した項目（`R`・`C`）は、`XY <新しいパス>` の次の NUL 区切りに `<元のパス>` が続く

## 変更内容

### 確かめの範囲（`invoke-codex.ps1`）

- `review` のときは、いつも `git status --porcelain -z -uall` の**すべての項目**を見る。NUL で区切った項目のうち、空の項目（出力の末尾）は飛ばす。各項目のパス（`XY ` の後ろ）を `$SecretPatterns` と照らす。X か Y のどちらかが `R` か `C` の項目は、次の NUL 区切りに `XY ` の付かない元のパスが続くので、それも照らす
- `-Base` のときは、それに加えて `git diff --name-only --no-renames -z <Base>...HEAD` のすべてのパスを照らす（`--no-renames` で、名前を変えたファイルを「元の名前の削除」と「新しい名前の追加」に分け、両方のパスを出させる。付けないと新しい名前しか出ず、`.env` → `env.example` のような名前の変更がすり抜ける）。`git diff` が失敗したら（基準ブランチが無いなど）、呼ばずに止める
- どれか1つでも当たれば、健さんを呼ばずに止める（終了コードは今の `Stop-Wrapper` と同じ）
- 照らし方（`Test-SecretPath`：`\` を `/` に、小文字にそろえてから照らす）と `$SecretPatterns` は変えない

### テスト（`test-invoke-codex.mjs`）

- **本物の健さんは絶対に呼ばない。** OS の一時ディレクトリに偽物の `codex`（`codex.cmd` と `codex.ps1` の両方。呼ばれたら、決めた場所に印のファイルを書いて、終了コード 0 で終わるだけ）を置く
- ラッパーを呼ぶ子プロセスの環境は、テストが作り直す（今の PATH を引き継がない）。**仮のリポジトリを準備する `git`（`init`・`add`・`commit`・`mv` など）も、同じ作り直した環境で動かす**（親の `GIT_DIR`・`GIT_WORK_TREE` を引き継ぐと、準備の `git` が呼び元のリポジトリを触りうるため。健さんが確かめた）
  - `PATH`：偽物のディレクトリ、`git` の実行ファイルがあるディレクトリ、Windows の `System32` と `System32\WindowsPowerShell\v1.0` だけ。本物の `codex` があるディレクトリ（npm のグローバルなど）は入れない（`PATHEXT` によっては `codex.cmd` が候補にならず、PATH の後ろの本物の `codex.ps1` が選ばれるため。健さんが PowerShell 5.1 で確かめた）
  - `PATHEXT`：`.COM;.EXE;.BAT;.CMD;.PS1` と決めて渡す
  - git の環境変数：今の環境の `GIT_` で始まる変数（`GIT_CONFIG_PARAMETERS`・`GIT_DIR` など）は、大文字小文字を問わずすべて引き継がない（`GIT_CONFIG_PARAMETERS` に `diff.renames=false` が残ると、下の固定が負けるため。健さんが確かめた）
  - git の設定：`GIT_CONFIG_COUNT=1`・`GIT_CONFIG_KEY_0=diff.renames`・`GIT_CONFIG_VALUE_0=true` を渡し、ラッパーの中の `git diff` でも名前の変更の検出を必ず有効にする（利用者が `diff.renames=false` だと、`--no-renames` を付け忘れた実装でも元の名前が出てしまい、テストが付け忘れを見逃すため。健さんが確かめた）
- **テストの最初に、その環境の子プロセスで `Get-Command codex` が偽物のディレクトリのものを指すか確かめる。** 違ったら、ラッパーを1回も呼ばずに、テストを終了コード 1 で落とす
- OS の一時ディレクトリに仮の Git のリポジトリを作り、`powershell.exe -NoProfile -ExecutionPolicy Bypass -File <ラッパー> -Mode review -Task t -WorkingDirectory <仮のリポジトリ>`（`-Base` の場合は `-Base <ブランチ>` も）を呼ぶ。終わったら仮のリポジトリと偽物を消す
- **止まる**（偽物の印が無く、ラッパーが秘密情報の言葉で止まる）ことを確かめる場合
  - 未追跡の `.dev.vars`（今までの場合）
  - ステージした `.dev.vars`
  - 追跡していて書き換えた `wp-config.php`（ステージしていない）
  - 名前を変えて、**新しい名前**が秘密情報（`git mv a.txt .env`）
  - 名前を変えて、**元の名前**が秘密情報（`git mv .env a.txt`）
  - `-Base` で、基準ブランチの後のコミットで `.kv/x` を足した
  - `-Base` で、基準ブランチの後のコミットで `.env` を `env.example` に名前を変えた（20行ほどの `.env` の1行だけを変える。テストの中で、先に `git diff -M --name-status <Base>...HEAD` が `R` を出す（`-M` で、利用者の `diff.renames` の設定に左右されないようにする）＝git が名前の変更と読んでいることを確かめる。`R` でなければテストを落とす。`--no-renames` を付け忘れた実装を見分けるため）
  - `-Base` で、基準ブランチとの差分は秘密情報でないファイルだけだが、未コミットで `.dev.vars` をステージした（`-Base` のときも未コミットの変更を見ていることの確かめ）
  - `-Base` で、無い基準ブランチを渡した（`git diff` が失敗するので止まる。止まるときの言葉は秘密情報ではなく、基準ブランチの失敗）
- **止まらない**（偽物の印がある＝健さんを呼ぶところまで進んだ）ことを確かめる場合
  - 作業ツリーがきれい（変更なし。`git status` の出力が空）
  - 秘密情報でないファイル（パスに空白と日本語を含む）を、未追跡・ステージ・書き換えた
  - `-Base` で、基準ブランチの後のコミットが秘密情報でないファイルだけ
- 偽物は返事を書かないので、止まらない場合のラッパーの終了コードは 0 でなくてよい。見るのは偽物の印の有無だけ
- テストは、確かめた場合の数と通った数を出し、1つでも落ちたら終了コード 1 で終わる。飛ばす場合は無い（偽物を使うので、本物の `codex` の有無に左右されない）

### データの流れ

- `review`：ラッパー → `git status --porcelain -z -uall`（と `-Base` なら `git diff --name-only --no-renames -z <Base>...HEAD`）→ すべてのパスを `$SecretPatterns` と照らす → 当たれば止める／当たらなければ健さんを呼ぶ
