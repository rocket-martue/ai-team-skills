## 目的

計画書（plan.md）はファイルに書くので、まーちゅうが自分で開かないと読めない（プランモードと違って画面に出ない。スマホからは特に見づらい）。承認を頼むときに、まーちゅうが plan.md を開ける形で渡し、要点を返事にまとめる決まりを、plan-writer に足す。あわせて、反映のたびに「テンプレートは別に直す」としてきた Ganesha.md の「Bash」を「Bash・PowerShell」にそろえる。

## 背景・前提

- まーちゅうの言葉（2026-10-06）：「このスキルだと、plan モードじゃないからガネーシャが立てた計画が見れないのが難点だね」。案 A（承認を頼むとき、plan.md をまーちゅうが開ける形で渡し、要点を返事にまとめる）を選んだ。案 B（プランモードの承認の画面に出す）は、プランモードの承認を承認欄へ写そうとして Claude Code の安全チェックに止められた経緯（2026-10-04）があるので採らない
- 「開ける形」：**ファイルを送るツールが使えるときは、必ずそれで plan.md を送る**（例：Claude Code の SendUserFile。2026-10-06 に、まーちゅうがスマホから送られた plan.md を読めた）。**それに加えて、返事にファイルの場所（実際の場所の絶対パス）を書く**。VS Code の拡張のリンク（`[plan.md](...)`）は決まりに入れない（下の箇条のとおり、開けたり開けなかったりで頼れない）
- **VS Code の拡張のリンクは、開いているワークスペースの中のファイルしか開けない。** 2026-10-06 に、ワークスペースの外（リポジトリの外の worktree）の plan.md へのリンクを、絶対パス（`C:/...`）と `file:///` の2つの形で置いたが、どちらも開かなかった（まーちゅうが確かめた）。さらに、複数のフォルダを開いたワークスペースでは、2つ目以降のフォルダの中のファイルもリンクで開かないことがある（Claude Code のイシュー anthropics/claude-code#67565 の報告。健さんが見つけた。今の拡張での再現は確かめていない）。だから、リンクは決まりに入れない
- 返事に書くパスは、ファイルの実際の場所の絶対パスでよい（返事は Git に入らない。「worktree のパスはリポジトリの根からの相対パスで渡す」は、メジェド・健さん・スキルどうしの決まりで、まーちゅうへの返事には当たらない）
- テンプレートの `repo-files/docs/team/Ganesha.md` の「絶対にしないこと」の1行目は「Bash 経由の書き込みは止まらないので、Bash で回り込まない」のまま。hook-scope（ai-team-skills PR #10）で common-rules.md を「Bash・PowerShell」にしたが、Ganesha.md は対象外だった。voice（PR #8）と channel（PR #78）の反映では、写しの側だけ2か所とも「Bash・PowerShell」に直した。site と hub の写しはまだ古い（2か所とも「Bash」）。site の反映は、この PR のマージ後の版を写すので、そこでそろう
- このリポジトリには phpcs が無い。このタスクは Markdown だけなので、チェックコマンドは無い（メジェドの報告の「チェックコマンドの結果」は「無い」と書く）
- このリポジトリはテンプレート置き場なので、`docs/team/` は `repo-files/docs/team/` に、`.claude/` は `claude/` にある。メジェドに頼むときは、作業ツリーのパスと、この読み替え（最初に読む common-rules.md・workflow.md の場所）を頼む文に書いて渡す（今までのタスクと同じ）
- 4リポジトリへの反映は、このタスクではしない（site・hub の反映は、この PR のマージの後の版を写す）
