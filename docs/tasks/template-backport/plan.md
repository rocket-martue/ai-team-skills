## 目的

## 変更内容

### 書く中身（言い回しはメジェドに任せる。意味はこのとおり）

- diff-reviewer：hub・site と同じ文（「`.md` の指摘もあれば、そのあとで次と同じように直す」）を、コードの指摘の箇条の最後に足す
- common-rules：hub・site と同じ文（「クライアント名・実ドメイン・slug をコード・テスト・コミットメッセージに書かない」）にする
- README の「導入方法」の最初に1段足す：テンプレートの写す版を先に決め、その版の中身から写す（やり方は「テンプレートを直した後の反映」の「写す版を決める」と同じ）。最後に1段足す：導入の PR の題名に、その版を「（ai-team-skills <版>）」の形で書く（次の反映の始まりになる）
- README の「テンプレートを直した後の反映」の節
  - 各リポジトリのセッションで行う（そのリポジトリのフックと権限が効くため）。頼み方の例：「rocket-martue/ai-team-skills の最新を反映して」（反映のイシューがあれば、その番号も）
  - 前回の版：そのリポジトリの前回の**全体の反映**の PR の題名に書いた版。その後に、部分的な反映（一部のファイルだけを先に入れたもの）や反映先での戻しがあれば、差分に出てくるので、中身で見比べる
  - 写す版を決める：最初にテンプレートを `git -C <テンプレート> fetch origin` し、`origin/main` のコミットを写す版として plan.md に書いて固定する。作業の途中でテンプレートが進んでも、その版のまま反映する（計画・実装・PR の題名で版をそろえるため）。その版の中身は、`git -C <テンプレート> show <写す版>:<パス>` や、その版を指定した `git diff` で読む。テンプレートのチェックアウトのファイルからは写さない（`fetch` だけでは作業ツリーが古いままで、記録した版と中身がずれるため）
  - 前回の版が分からないとき（前回の全体の反映の PR の題名に版が無いなど）：差分ではなく、写す版のファイル全体と、そのリポジトリのファイルを見比べる（最初の導入と同じ）
  - 差分を見る：テンプレートの `git log <前回の版>..<写す版>` と `git diff <前回の版> <写す版>` を、`claude/`・`repo-files/docs/team/`・`repo-files/gitignore.snippet`・`repo-files/CLAUDE.md.snippet`・`repo-files/codex/AGENTS.md` に絞って見る。置き場所の対応は「導入方法」のとおり（`claude/` → `.claude/`、`repo-files/docs/team/` → `docs/team/`）
  - 取り入れる：変更ごとに、そのリポジトリの固有の上書き（チェックコマンド・`SECRET_PATTERNS`・レビューの観点・plan.md の雛形・settings.json の allow など）と見比べて、取り入れるかを決める。取り入れないものは、PR 本文の「残したもの」に理由を書く。テンプレートが持たないもの（ボードの Status など）を使っているなら、固有の上書きとして残してよい
  - 反映先で足した直しのうち、どのリポジトリにも効きそうなものは、テンプレートのイシューに書く（テンプレートに戻すため）
  - 流れは、ふつうのタスクと同じ（plan-writer → メジェド → diff-reviewer → 健さん → PR）。ただし、テンプレートでレビュー済みの変更を写すのが中心なので、承認前の Fable は省く。ほかは workflow.md どおり（承認前の健さんの consult、チェックが2回以上落ちたときの consult、PR の前の review）（まーちゅうの判断・2026-10-09）。まーちゅうに頼まれたら Fable も回す
  - 全体の反映の PR の題名に、写した版を「（ai-team-skills <版>）」の形で書く（次の反映の始まりになる）。部分的な反映では、題名にこの形を書かない（次の反映の始まりと取り違えないため）。版は本文に書く
  - `repo-files/codex/AGENTS.md` が変わっていたら、PR の「マージの後」にその差分を書いて伝える。各 PC の `<CODEX_HOME>/AGENTS.md` は、まーちゅうの許可を得てから、見比べて合わせる（リポジトリの外。個人の設定を上書きしないため。「導入方法」の5と同じ）
  - マージの後は、そのリポジトリのメインのチェックアウトを追いつかせ、そのリポジトリのウィンドウを再読み込みする（`.claude/` はセッションの開始時に読まれるため）
