## 目的

PR の前（`K3`）とチェックが2回以上落ちたとき（`K2`）でも、健さんの代わりに `/code-review` を選べるようにする。コミットの前の作業ツリーの差分（消した行・未追跡のファイルも含む）を、秘密情報を渡さずに `/code-review` に見せる。

## 背景・前提

- #43（PR #47）で、承認前のレビュー役を選べるようにした（`repo-files/docs/team/workflow.md` の言葉の決まり「レビューの道」）。PR の前と K2 は「健さんだけ（`/code-review` は選べない。別のイシュー（#45）で決める）」（同 `:90`）
- 切り出した理由（#45 の本文）：このチームは PR の前の確認をコミットの前に回す（健さんの `review` は `--uncommitted`）。`/code-review` は対象（PR・ブランチ・パス）を1つ取る作りで、コミットの前の worktree の差分を見せる方法が無く、変わったファイルのパスを渡すと、消した行が見えず、秘密情報のファイルもそのまま渡る
- 確かめたこと（#45 のコメント2つ。2026-10-12）
  - `git diff HEAD` で作ったパッチのファイルのパスを `/code-review high --max-findings default <パッチ>` に渡すと、差分として読む。消した行（チェック・テストの `assert`）とバグが指摘に出て、「隠すためにテストも消している」（K2 の「直ったのか隠しただけか」に当たる）も出た。差分の外への指摘は出なかった
  - 未追跡のファイルは、`git diff --no-index -- /dev/null <ファイル>`（違いがあるときの終了コード 1 は正常）でパッチに足せる。インデックスは触らない
  - `docs/tasks/<タスク名>/` は `:(exclude)` で外せる
  - `--no-renames` を付けると、名前の変更でファイル全体が2回入る。付けなければ短い形
  - 共有モジュール（`claude/hooks/ai-team-config.mjs check`）に変わったパスを渡すと、健さんのラッパーの `review` と同じ判定で秘密情報を止められる（`.env.local` で終了コード 3）
- まーちゅうの決めたこと（#43 の本文とコメント。2026-10-11・12）：健さんを呼ばないときは、代わりに `/code-review` を、採る指摘が0になるまで最大5回回す。承認前と PR の前の両方に当てる。K2 は PR の前の道に合わせる（#43 の計画の確認事項。2026-10-12）
- パッチを作るところ（秘密情報の照らし合わせ・パスの集め方・`docs/tasks/<タスク名>/` を外す）は、健さんのラッパー（`claude/skills/codex/scripts/invoke-codex.ps1`）にモードを足して、そこでする（ガネーシャの案）。ラッパーの `review` が、渡す前のパスの集め方（`:217-252` 付近。`git status --porcelain -z -uall` と、名前の変更の元の名前）と秘密情報の照らし合わせ（共有モジュール）をもう持っているため。ガネーシャが手で打つと、照らし合わせの抜けや、パスの集め方のずれが起きる（#43 で保存をラッパーに寄せたのと同じ理由）

- `make-patch` の動き
  - `codex` を呼ばない（`codex` が PATH に無くても止まらない）。`-PromptFile` も要らない
  - `-Task` の確かめ（必須・英数字で始める）は今までどおり。`-OutFile` が無ければ止まる
  - 渡す前の確かめは、今の `review` と同じ（パスの集め方と秘密情報・設定ファイルの確かめ）に、実体のパスの照らし合わせを足したもの。パッチにはファイルの中身が入るので、親のディレクトリがジャンクション・シンボリックリンクで、実体が秘密情報（例：`vault/a.md` の実体が `.kv/a.md`）のものも止める。共有モジュールの入口 `check` に `--resolve-real` を足し、付けたときは、各パスについて `realPath(<根>/<パス>)` を求め、その実体のパスの `realPath(<根>)` からの相対パスも照らす（実体が根の外なら止める。`realPath()` が null（リンク切れ）なら止める）。`make-patch` は `--resolve-real` を付けて呼ぶ。`review` には付けない（今の動きを変えない）
  - パスの集め方は今の `review` と同じ（`git status --porcelain -z -uall`。名前の変更・写したものは元の名前も）。ただし `make-patch` では `--ignore-submodules=none` を付ける（パッチと同じく、サブモジュールの参照の変更を拾うため。`review` の今の動きは変えない）。秘密情報と設定ファイルの確かめは、作業の根とメインのチェックアウトの根で行い、当たれば止まる・壊れていれば止まる。`-Base` は使わない（コミットの前の差分だけを作る）
  - パッチを作る：(1) `git diff HEAD -M --no-ext-diff --no-textconv --no-color --submodule=short --ignore-submodules=none -- . ":(exclude)docs/tasks/<Task>/"`（利用者の Git の設定に左右されないように、次をはっきり付ける。`-M`：名前の変更を見つける（`diff.renames=false` でも）。`--no-ext-diff`・`--no-textconv`：外部の diff や textconv で、消した行が見えなくならないように。`--submodule=short`：サブモジュールの中の変更を展開しない（`diff.submodule=diff` でも。照らし合わせたのはサブモジュールのパスだけなので、中身を渡さないため）。`--ignore-submodules=none`：サブモジュールの参照の変更を消さない（`diff.ignoreSubmodules=all` でも）。`--no-color`：色の制御文字を入れない（`color.diff=always` でも）。`--no-renames` は付けない。終了コードが 0 でなければ（HEAD が無い・Git のリポジトリでないなど）、「差分が無い」とは扱わず終了コード 1 で止まる）、(2) `git ls-files --others --exclude-standard -z -- . ":(exclude)docs/tasks/<Task>/"`（終了コードが 0 でなければ終了コード 1 で止まる）で出た未追跡のファイルの1つずつに `git diff --no-index --no-ext-diff --no-textconv --no-color -- /dev/null <ファイル>`（終了コード 0 と 1 は正常。それ以外は止まる）。ただし、`--no-index` は取れなかったときも 1 を返すので、渡す前に、未追跡の項目が作業の根の下のふつうのファイル（`Test-Path -PathType Leaf`）かを確かめ、そうでなければ（`nested/` のような入れ子のリポジトリ・ディレクトリなど）終了コード 1 で止まる。名前がちょうど `-` のファイルは、Git が標準入力と読むので `./-` にして渡す。(1) の後ろに (2) をつなげ、UTF-8（BOM なし）で `-OutFile` に書く（あれば書き換える）
  - できたパッチが空なら、ファイルを書かずに終了コード 4 で止まる（「見せる差分が無い」。呼んだ側は保留する）
  - 書けたら `PATCH: <-OutFile の絶対パス>` と、パッチに入ったファイルの数を出して、終了コード 0 で終わる
