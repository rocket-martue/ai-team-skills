## 目的

健さん（Codex）の `review` と `consult` は read-only のまま呼び、テストは走らせない、と決まりに書く（#36 の案A）。代わりに、健さんにはテストのコードを読ませて、差分で壊れそうなテスト・弱められたテストが無いかを見させる。健さんの返事に毎回「テストは走らなかった」が入って PR に注記が要る、も無くす。

（最初の承認では案B（リポジトリは読むだけ・一時ディレクトリだけ書ける permissions profile）で実装したが、本番の review で、健さんがファイルを読む道具が sandbox の準備で毎回失敗し、review そのものができなかった。まーちゅうの判断で案A に戻す。経緯は「背景・前提」と review.md の第3回・第4回）

## 背景・前提

- 今のラッパー（`claude/skills/codex/scripts/invoke-codex.ps1`）は、`consult` を `codex exec ... -s read-only`、`review` を `codex exec review ... -c sandbox_mode=read-only`、`image` を `codex exec ... -s read-only` で呼ぶ。read-only の sandbox では一時ディレクトリにも書けず、vitest などのテストは EPERM で止まる。健さんの review は、このリポジトリでも swx-inventory-hub でも、毎回「テストは実行していません」だった（#36）
- 案B を試した結果（2026-10-09〜10。review.md の第3回・第4回）
  - `codex sandbox -P <profile>`（モデルを呼ばない）では、`:read-only` を元に `:tmpdir` だけ write にした profile で、TEMP に書けてリポジトリに書けず、vitest も通った
  - しかし本番の `codex exec review` では、健さんがファイルを読む Codex 自前の node（`cua_node`）が、書ける場所がある sandbox の準備で、`node_repl.exe` の runtime の確かめ（`runtime read/execute validation failed`）に毎回失敗し、リポジトリも差分も読めなかった（3回とも。Codex のデスクトップアプリを閉じても同じ）。read-only（書ける場所 0）のときはこの確かめが起きない
  - この PC の Codex は codex-cli 0.160.0、`[windows] sandbox = "elevated"`
- テストの結果は、メジェド（実装・修正のたび）とガネーシャ（レビューのたび）が、common-rules.md の「チェックコマンド」で毎回取っている（`repo-files/docs/team/common-rules.md:33` のコメント）。健さんがテストを走らせなくても、テストを見ずに PR に進むことにはならない
- 健さんは、テストを走らせなくても、読んでテストのバグを見つけたことがある（`test-invoke-codex.mjs` が CP932 の出力を UTF-8 で読み、日本語の一時パスで落ちる件。#36 の検討のときに、このリポジトリの過去の返事で確かめた）
