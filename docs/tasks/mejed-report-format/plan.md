## 目的

メジェドの報告の「変更したファイル」をリポジトリの根からの相対パスで書かせ、「計画との差分」には計画と違うことをしたときの中身だけを書かせる。報告の5行の形（行の数と順番）は変えない。

## 背景・前提

- 報告の形式は `claude/agents/mejed.md` の「報告の形式」にある5行（63〜73行目）。「変更したファイル：パスの一覧」「計画との差分：あれば。無ければ「なし」」としか書かれていない
- 反映したリポジトリの最初のタスクで、「変更したファイル」がローカルの絶対パスで書かれ、「計画との差分：なし」の後ろのかっこに何を直したかが書かれた（#17 の背景）
- このリポジトリでも同じ形が出た：#19 の修正の報告で「計画との差分：なし（settings.json とフックのテストは触っていない。手順の順番も変えていない）」、実装の報告で「変更したファイル」の見出しに worktree の絶対パスを書いた
- 健さんには「リポジトリの根からの相対パスで書く」と決めている（`repo-files/codex/AGENTS.md:34`）。報告を review.md や PR に写すとき、絶対パスだと手で直す手間がかかり、公開するリポジトリではローカルのパスが残る原因になる
- worktree で作業するときは、その worktree の根からの相対パスにする（worktree の中のパスはメインのチェックアウトと同じ形になる）
- ガネーシャの受け方（`claude/skills/delegate-to-mejed/SKILL.md` の「メジェドの報告の受け方」）には足さない（まーちゅうの判断・2026-10-09）。受け方が見るのは「結果」と「途中で2回以上落ちたチェック」の行だけで、diff-reviewer が計画と照らすのも実際の差分なので、報告の書き方は誰も確かめない。それでも、書き方が崩れても差分のレビューの正しさには響かず、報告を review.md や PR に写すときにガネーシャが直せるので、規則は増やさない。この決まりは、メジェドが自分で守るためのもの
- このリポジトリのチェックコマンド（このタスクに限る）：`node claude/hooks/test-guard-code-edit.mjs` と `node claude/skills/codex/scripts/test-invoke-codex.mjs`（どちらも変えないことの確かめ）

## 変更内容

### 書く中身（言い回しはメジェドに任せる。意味はこのとおり）

- 5行のひな形の「変更したファイル」の行：リポジトリの根からの相対パスで、ファイルごとに何をどう直したかを短く添える
- 5行のひな形の「計画との差分」の行：計画と違うことをしたときだけ、その中身を書く。無ければ「なし」とだけ書く
- ひな形の下の箇条に足す
  - 「変更したファイル」の行のパスは、リポジトリの根からの相対パスで書く（worktree なら、その worktree の根から）。ドライブ文字やユーザー名を含む絶対パスは書かない（報告は review.md や PR に写すことがあり、公開するリポジトリにローカルのパスが残るため）
  - ほかの行（停止の理由に書く「止まったコマンドそのもの」など）は、この決まりの外。コマンドは書き換えずにそのまま書く（common-rules.md の「作業の進め方」）
  - 「計画との差分」の「なし」の後ろに、かっこで説明を足さない。何を直したかは「変更したファイル」の行に書く（差分があったのか無かったのかを読み違えないため）
- 5行の行の数と順番、「途中で2回以上落ちたチェック」の箇条は変えない
