### 1. PR の後の段（レビューの道）

### 2. adversary.md のタイミング `pr`

- description を「壊しに来る役。計画書（タイミング plan）や PR の差分（タイミング pr）を、壊す側から読んで指摘だけを返す。直さない・コードを書かない。実装の判定には使わない」の形にする
- 「最初に必ず読むこと」の plan.md の箇条は、`plan` のときと `pr` のときで読まないもの（「承認前の確認」の節）を同じにする。`pr` のときは、`docs/tasks/<タスク名>/review.md` も判断に使わない（ガネーシャの採否が入っているため）
- 「受け取るもの」に `pr` を足す：タイミングの名前 `pr`、タスク名と plan.md のパス、作業ツリーのパス、差分の取り方（作業ツリーに `cd` してから `git diff -M --no-ext-diff --no-textconv --no-color --submodule=short --ignore-submodules=none origin/<既定ブランチ>...<ブランチ> -- . ":(exclude)docs/tasks/<タスク名>/"`。付け足しは健さんのラッパーの `make-patch` と同じ（`-c core.quotepath=false` だけは、settings.json の ask（`git -c`）に当たるので付けない。日本語のパスが引用符と8進で出ることがあるが、読むのには困らない）で、利用者の Git の設定（外部の差分の道具・textconv）に左右されず、外のコマンドを起動しないため。plan.md と review.md はコミット済みで差分に出てしまうので外す。plan.md は「承認前の確認」の節を読まずに別に Read で読む）。`git fetch origin` は呼ぶ前にガネーシャが打つ（adversary は読むだけのコマンドしか打たないため）。`git -C`・`git -c`・`gh pr` は使わない（settings.json の ask に当たり、バックグラウンドで止まるため）
- 「問い（pr）」を足す
  - 差分が plan.md の目的と完了条件を満たしているか
  - 差分の手順・コードを実際に動かす場面で壊れるところ（順番・前提・失敗したときの扱い）
  - 差分が新しく生む食い違い（同じリポジトリのほかの文書・スキル、ほかのリポジトリ（gh-* など）との約束）
  - 外部のサービスや GitHub の振る舞いに頼るところで、確かめていないもの（推測と書く）
- 「報告の形式」の「場所」に、`pr` のときは差分の `ファイル:行` を書く、を足す
- 「絶対にしないこと」に、PHP・composer・npm などのプロジェクトのツールを起動しない（ファイルを読んで判定する。動かして確かめたいことは推測と書いて確かめ方を添える）を足す（Windows のスマート アプリ コントロールに止められたことがあるため。2026-10-12）
- 「PR にコメントしない」を「絶対にしないこと」に足す（報告はガネーシャにだけ返す）

### 3. Copilot を前提にしない書き方

- delegate-to-mejed `:49`「Copilot のレビューの回数は workflow.md に従う」を、「PR に付いたレビュー（人・bot）と PR の後のレビュー（Fさん）の扱いと回数は workflow.md に従う」にする

### 4. バックグラウンドで回す（M・F・K・J とチェック）

- workflow.md に言葉の決まり「バックグラウンド」を足す
  - メジェド・Fさんは Agent ツールの `run_in_background` で、健さんはラッパーを Bash ツールの `run_in_background` で、純ちゃんは「`/code-review` を呼んで結果をそのまま返す」頼みのサブエージェント（general-purpose）を Agent ツールの `run_in_background` で回す
  - 時間のかかるチェックコマンド（テスト・`claude plugin validate`・各リポジトリのチェックコマンドのうち時間のかかるもの）も Bash ツールの `run_in_background` で打つ。すぐ終わる確かめ（`git status`・grep など）はそのまま
  - 回したら、終わりの知らせを受けてから結果を読む。知らせが来る前に結果を推測して進めない
  - 待つ間にまーちゅうに頼まれたことは、回している役と同じファイルを触らない範囲で受ける
  - 純ちゃんのサブエージェントへの頼みの文：Skill ツールで `code-review` を、ガネーシャが決めた引数（レベル・`--max-findings default`・対象）そのままで呼び、返った結果の文を書き換えずに返す。ファイルを書き換えない・git を打たない。結果の保存（`save-code-review`）は今までどおりガネーシャがする
  - 純ちゃんをサブエージェントの中で呼んだとき、まーちゅうが引数なしで呼んだときの既定が変わるかは確かめていない。workflow.md `:102` と plan-writer `:23` の「既定が呼んだレベルに変わった」と添える文を、「既定が呼んだレベルに変わったかもしれない（サブエージェントで呼んだときは確かめていない）」にする
