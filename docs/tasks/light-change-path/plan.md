### 書く中身（言い回しはメジェドに任せる。意味はこのとおり）

workflow.md の「簡単な修正の道」の節：

- 使ってよい範囲：決まりを持たない説明の文書（README など）の、`.md` の小さな直しだけ。誤字・言い回し・リンクの直しや、手順の説明・注意書きの追記など
  - 入れないもの（置き場所にかかわらず、役割で外す）：規約と作業の流れ（`docs/team/`。テンプレートのリポジトリでは `repo-files/docs/team/`）、根の `CLAUDE.md`、スキル・エージェント・フック・settings.json（`.claude/`。テンプレートのリポジトリでは `claude/`）、健さんの決まり（AGENTS.md）、コード、`docs/tasks/` の下の記録
- 入り方：ガネーシャが「簡単な修正の道で進めていい？」と、直すファイルとブランチ名を添えてまーちゅうに聞き、まーちゅうが OK と言ったときだけ。まーちゅうから「計画なしで」「健さんだけで」と頼まれたときも入ってよい。範囲に入るか迷ったら、ふつうの流れにするか、まーちゅうに聞く
- 流れ
  0. 作業ツリーを確かめる。`git status --short --branch` で未コミット・未追跡の変更が無いこと（健さんの review に全部渡るため）を確かめ、あれば止まって報告する。`git fetch origin` のあと、ブランチを切る（gh-issue などで worktree が用意されていればそれを使い、切らない）。ブランチの切り方は delegate-to-mejed の手順2と同じ。まーちゅうの OK には、このブランチを切ることが含まれる
  1. ガネーシャが直す。plan.md・review.md は作らない。直したら（手順3で直したときも）、common-rules.md の「チェックコマンド」を全部実行し、通ることを確かめる（通らなければ、範囲の外の変更が要るかを見て、要るなら手順4と同じく保留する）
  2. 健さんの review（PR の前の確認）を頼む。`-Task` には、直す中身を表すタスク名（英小文字のケバブケース）を付ける。タスク名は、メインのチェックアウト（`git worktree list` の1件目）に `docs/tasks/<タスク名>/` がまだ無い名前にする（ラッパーは worktree から呼んでも返事をメインのチェックアウトの下に残し、その返事の数で回数を数えるため）
  3. 健さんの返事を1件ずつ一次データで確かめる。採る指摘は、範囲の中ならガネーシャが直して、もう一度健さんに頼む。上限は「PR の前の健さん」と同じ（健さんを呼んだ回数で最大5回。採る指摘が0になったら止める）。回数は、メインのチェックアウトの `docs/tasks/<タスク名>/codex/` の review の返事のファイルの数で数える。まーちゅうに頼まれて回した回（上限の外）は、そのファイル名をまーちゅうへの報告と PR 本文に書き、数から引く。5回目でも採る指摘があれば保留する
  4. 採る指摘が、範囲の外のファイルや決まりの変更を要するなら、この道をやめて保留する。直しは作業ツリーに残したまま、まーちゅうに、ふつうの流れに移るか・直しを捨てるかを聞く。ふつうの流れに移るなら、plan-writer で plan.md を書き、残した直しを「対象ファイル」と「背景・前提」に書く
  5. 健さんを呼べなかったときは、「指摘なし」とは扱わず、保留する
  6. まーちゅうに報告する（変更したファイル・チェックコマンドの結果・健さんの返事の保存先・回ごとの採った指摘と見送った指摘と理由・健さんを呼んだ回数）。「コミットと PR をしていい？」と聞き、頼まれたらコミット・push・PR を作る（やり方は delegate-to-mejed の手順8と同じ。plan.md・review.md のリンクの代わりに、簡単な修正の道で通したこと、チェックコマンドの結果、健さんの回ごとの採った指摘・見送った指摘と理由・呼んだ回数（上限の外の回はその旨）を本文に書く）
  7. 健さんの返事を、全部の回の分、PR に貼る（貼る前の確かめは delegate-to-mejed の手順8と同じ）
- PR に付いたレビュー（Copilot・人）：diff-reviewer は使わない（plan.md が無いため）。ガネーシャが指摘を1件ずつ一次データで確かめ、直す指摘と直し方をまーちゅうに伝えて承認を得てから、範囲の中なら直し、チェックコマンドを全部実行して通ることを確かめてから、追加コミット・push し、スレッドに返信する（PR を作るときの OK は、PR の後の直しを含まない）。記録は、スレッドの返信と PR のコミットに残す（review.md は作らない）。修正の上限は「PR に付いたレビューによる修正依頼」と同じ最大3回で、PR に積んだ直しのコミットの数で数える。範囲の外を要する指摘は、手順4と同じく保留する
- 健さんの review は省かない
